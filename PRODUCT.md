# Product

## Register
product

## Users
BTech students learning distributed computing and presenting a practical demonstration on a laptop in a classroom. The main job is to follow a resource request from broadcast through replies, critical-section entry, and release.

## Product Purpose
Explain Lamport and Ricart–Agrawala mutual exclusion with actual process clocks and local decisions. Lamport uses independent request queues; Ricart–Agrawala uses deferred replies. A single dropdown changes the protocol and starts a fresh paused run. Show what happened, why, and why a process must wait.

## Brand Personality
Clear, calm, instructional. Use simple English for all live explanations.

## Anti-references
Unreadable dark labels, decorative glows, constantly pulsing cards, overlapping message labels, and a dashboard that separates the diagram from its explanation. Avoid elaborate modes, added frameworks, and unnecessary controls.

## Design Principles
- Put the current action and its explanation together.
- Explain with the real clock values and local conditions.
- Make REQUEST, REPLY, and RELEASE easy to distinguish.
- Show only the message types and entry conditions of the selected protocol.
- Keep the combined queue an observer overview, never a central permission mechanism.
- Optimize for laptop demonstrations; mobile design is outside this task.

## Accessibility & Inclusion
Readable text with WCAG AA contrast targets, keyboard-visible focus, explicit state labels, and reduced-motion support. No colour-only instructions.
